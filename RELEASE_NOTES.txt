pgsavvy v0.15.0

  Added opt-in full SQL access for the Linux/macOS machine CLI. Set a saved
  profile to cli_access: full and read_only: false to execute writes, DDL and
  maintenance commands within PostgreSQL privileges. Existing CLI policies and
  full profiles with read_only: true retain guarded read-only execution.

  confirm_writes and confirm_ddl can require per-invocation approval before
  credentials, SSH or database setup. Use the controlling terminal to type the
  exact connection name and yes, or pass both --approve and
  --confirm-connection NAME. SQL stdin remains separate. Approval is not cached;
  classification is heuristic, not a security sandbox or complete effects check.

  Writable full mode sends unparameterized SQL unchanged as one native batch,
  without an application transaction wrapper. Parameters support one statement;
  streaming COPY is rejected. JSON data.results retains command tags and
  positional rows, bounded to 256 results and an aggregate 100 default / 1000
  maximum rows. Guarded query output keeps its existing shape.

  Full-mode JSON adds execution status and possible-effects/prepared-transaction
  indicators. Unfinished local transactions are rolled back and reported as
  incomplete. Earlier commits or prepared transactions can survive a later
  failure; missing output, timeouts and history outcomes do not prove rollback
  or durability. Inspect database state before retrying SQL.

  Updated connection forms, JSON help/capabilities and operational/downgrade
  guidance. Opted-in CLI history records approval denials as blocked attempts.
  Expanded shipping-binary, terminal-approval and PostgreSQL 17/18 coverage for
  permissions, transactions, partial effects and bounded output.

  Native macOS acceptance remains pending; Windows machine commands remain
  unavailable. Before downgrading, stop automation, inspect outstanding effects
  and prepared transactions, and replace full profile values with supported
  policies. See docs/cli-query.md and docs/cli-contract.md for safeguards and
  recovery guidance; docs/cli-testing.md describes required native checks.

pgsavvy v0.14.0

  Added the macOS machine CLI for JSON help, capabilities, saved-connection
  discovery/testing, schema inspection and bounded read-only queries. Bare
  startup, version and update commands retain their existing interactive/legacy
  routes. Windows machine commands remain unavailable.

  macOS blocking pipes and output sockets use private workers in the same
  executable, with acknowledged destination writes and joined cancellation.
  Foreground interrupts preserve usable output workers for timeout reporting;
  inherited stream flags and socket options are not changed.

  Profile cli_access permissions and strict SSH host trust remain enforced;
  cli_history remains an independent opt-in. Machine keyring lookups reject
  items whose identity does not exactly match the requested credential reference.
  Existing macOS configuration and state paths are preserved; no migration is needed.

  Removed the inline CLI-history description from connection forms. Expanded
  Unix shipping-binary and PostgreSQL 17/18 machine-command test coverage.

  Native macOS acceptance is pending at release preparation. Linux tests and
  Intel/Apple Silicon cross-builds do not establish native runtime verification;
  see docs/cli-testing.md for the required Mac checks.

pgsavvy v0.13.0

  Added opt-in shared query history for the Linux machine CLI. Enable
  cli_history independently for each saved connection in YAML or the connection
  form. Recording is off by default and never grants database access or changes
  the CLI's read-only query policy.

  Opted-in attempts record original SQL, profile, completion time, duration and
  succeeded/failed/blocked outcome. History shows CLI/TUI sources and refreshes
  when activated. Display controls are sanitized; recalling SQL copies it into
  the editor without executing it. Blocked queries do not supply completions.

  History is bounded best effort, not an audit log; recording failures do not
  change query results or exit codes. Raw SQL literals and comments are retained,
  but bound parameter values and returned rows are not recorded. Disabling
  history stops future recording without deleting existing entries.

  New Unix history stores use owner-only permissions. CLI recording refuses
  unsafe existing stores rather than changing their permissions automatically.
  HISTORY_UPGRADE_REQUIRED can be resolved by opening the current TUI once.
  Cooperating connection writers now serialize changes and preserve concurrent
  CLI policy edits. See docs/cli-query.md for privacy and upgrade guidance.

  Before downgrading, stop all writers, back up configuration and make a
  WAL-consistent history backup. Remove cli_history keys and, for a v1 history
  predecessor, use the guarded offline rollback procedure in docs/cli-contract.md.
  History rollback loses source labels and maps blocked attempts to failed.

pgsavvy v0.12.0

  Added a Linux-only machine CLI for scripts and agent tools, without starting
  the TUI, interactive prompts, history or persistent logs. Discover commands,
  limits and exit codes through JSON help and the capabilities command.

  List and inspect saved connections offline; opt profiles into connection
  testing, paged schema/table listings, column/index details and foreign-key
  relationships with cli_access=metadata. Enable cli_access=row-read for bounded,
  parameterized, read-only queries from SQL files or stdin. Database access is
  disabled by default; the connection form now includes a CLI access selector.

  Machine commands return version-1 JSON with explicit completion/truncation
  flags and stable exit codes. Query values preserve PostgreSQL text and NULLs.
  Input, rows, cells, output and execution time are bounded, with cancellation
  and owned-resource cleanup. Credentials must resolve without prompts; SSH
  requires existing trusted host keys. Public errors omit raw backend details.

  Added CLI usage, contract, query, schema and testing documentation, plus
  PostgreSQL 17/18 integration coverage and native-platform fixture lanes.
  Windows/macOS adapters are preparatory only: their machine CLI entrypoints
  remain disabled pending full native verification. Existing TUI and legacy
  version/update commands remain available on their supported platforms.

  Before downgrading, stop profile writers and automation, back up connections,
  remove cli_access keys and validate the old loader against a rollback copy.
  See docs/cli-contract.md for the complete rollback procedure.
